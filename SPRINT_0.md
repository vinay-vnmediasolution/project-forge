# Sprint 0 — Foundation

## Sprint goal

Establish the smallest durable operating system needed to begin Project Forge with focus, continuity, and a clear definition of done.

## Scope

- Confirm repository access and current state.
- Create the README.
- Agree the project charter and definitions of done.
- Create roadmap v1 and curriculum v1.
- Record the initial backlog.
- Add contribution and agent guidance.
- Create a minimal GitHub issue and milestone structure.
- Make Sprint 1 ready for planning.

## Explicitly not in scope

- Website or documentation portal
- Logo, colour palette, or other branding assets
- Newsletter, community, social accounts, or publishing automation
- Application code
- Multiple project repositories
- Detailed planning beyond the first learning block

## Definition of done

Sprint 0 is done when:

- the repository contains all foundation files;
- Vinay has reviewed and accepted the charter or requested explicit changes;
- GitHub has a small executable issue backlog;
- Sprint 0 and Sprint 1 milestones exist;
- Sprint 1 has one clear goal, a bounded candidate build, and agreed capacity;
- any unresolved work is visible rather than implied complete.

## Review prompts

- Is the mission specific enough to guide trade-offs?
- Does the definition of done encourage completion without turning every exercise into a production platform?
- Is the first build useful, small, and relatable?
- What should be removed before Sprint 1 starts?

## Retrospective

Complete at sprint close:

- What created momentum?
- What introduced friction?
- What should Project Forge start, stop, and continue?
